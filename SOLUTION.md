# Как устроен Crown

Три учебных задания склеены в один сервис, иначе получается зоопарк из «скрипта», «прокси» и «compose-файла», которые в жизни всё равно стоят рядом.

- **Задание 1** — разбор PDF извещения через Gemini.
- **Задание 8** — шлюз: ключ в БД, лимит, 429, без ключа нельзя.
- **Задание 9** — три контейнера и линтеры на пуш.

Ниже — как это ездит по запросу.

## Поток

```
браузер / curl
    │
    ▼
Caddy (TLS, crown.skykraft.su) ──► FastAPI :8090
                                      │
                     cookie crown_api_key (httpOnly)
                                      │
                    ┌─────────────────┼─────────────────┐
                    ▼                 ▼                 ▼
               PostgreSQL          Redis            Gemini
               ключи, история      окно 5/мин       выжимка
```

1. `POST /api/keys` пишет строку в `api_keys` (sha256 ключа, не сам ключ) и ставит cookie. Повторный вызов с живой cookie новую запись не плодит.
2. Любой защищённый путь без cookie / с отозванным ключом → **401** и страница ошибки, не пустой 500.
3. `POST /api/summarize` читает PDF (магия `%PDF-`, потолок 50 МБ). Если этот же файл этим же ключом уже разбирали — отдаём запись из Postgres, **лимит не тратим**.
4. Иначе Redis: скользящее окно 60 секунд, максимум 5 хитов на `api_key.id`. Шестой → **429** + `Retry-After`.
5. Текст через pypdf. Если его почти нет (скан) — PDF уходит в Gemini через Files API (inline base64 на 50 МБ не влезет). Если текст есть — уходит он: дешевле и быстрее. Caddy принимает тело до 55 МБ, приложение — 50 МБ чистого PDF.
6. Ответ модели парсится как JSON (ограда \`\`\`json снимается). Пишем `summaries` и отдаём карточку.

Лимит висит на ключе, не на IP. Ключ унесли на другой хост — счётчик тот же.

## Ключ и cookie

Сырой токен живёт только в httpOnly cookie (`Secure` на проде, `SameSite=Lax`). В JSON выдачи он есть **один раз**, чтобы curl мог положить его в jar. JS ключ не читает — так и задумано.

В таблице — `key_hash` + короткий `key_prefix` для плашки в шапке. Отзыв ставит `revoked_at` и сбрасывает cookie.

## Redis

Не «чтобы в compose было три контейнера», а потому что Postgres для окна «N запросов / минута» неудобен: либо гонки, либо лишние локи.

Скрипт Lua атомарно:

1. выкидывает хиты старше окна;
2. если уже `>= 5` — отказ и `retry_after` по самому старому хиту;
3. иначе пишет текущий timestamp в ZSET и ставит TTL.

Peek для UI (`GET /api/keys/me`, шапка) окно не двигает.

## Gemini

Ключ: `API_GMINI` (или `API_GEMINI`). Модели — цепочка `GEMINI_MODEL` + `GEMINI_MODELS`. На 429/404 берём следующую, как в hh-tools: free-tier Google часто режет одну модель и спокойно пускает другую.

Выход наружу с этой машины идёт через SOCKS (`AI_PROXY_URL`), иначе Google иногда не открывается из контейнера.

Промпт жёстко просит JSON с полями суммы, сроков, требований и штрафов. Если в бумаге поля нет — `null` / пустой список, без фантазий. На это рассчитывать на 100% нельзя: модель врёт. Для учебного шлюза этого достаточно; в бою поверх нужен второй проход правилами/regex по НМЦК.

## Ошибки

Один обработчик на `AppError` / HTTP / validation / всё остальное. Если `Accept` хочет HTML — страница с кодом и короткой фразой (401 сразу предлагает выдать ключ). Если JSON — `{"ok":false,"error":"...","message":"..."}`. 5xx пользователю без стека; стек только в лог контейнера, без токенов.

## Почему не отдельный Vue

Задание 1 — FastAPI и PDF. Задание 8 — шлюз. Третий фронтовый контейнер здесь не даёт ничего, кроме деплоя. UI — серверные шаблоны, адаптив от 320. История и выдача ключа — обычные формы, cookie уезжает сама.

## CI

На пуш в `main`: `black --check` и `flake8`, плюс pytest без живого Gemini (парсер, лимитер, PDF-магия, cookie-хеш).

## Что сознательно не делали

- Очередь «загрузил PDF → потом забери результат». Один uvicorn, один файл, ответ в том же запросе. Caddy ждёт до 180 с.
- Хранение самих PDF. Нужен хеш для дедупа, не архив закупок.
